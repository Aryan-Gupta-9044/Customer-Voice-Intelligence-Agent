# Customer Voice Intelligence Agent

## Overview

Customer Voice Intelligence Agent is a Streamlit-based Python application for analyzing customer reviews.
It ingests review CSVs, normalizes text, scores sentiment, extracts themes, analyzes temporal trends, and answers business questions using evidence-backed retrieval.

## Features

- Upload review CSVs or use bundled sample data
- Clean and normalize review text
- Sentiment scoring with positive/neutral/negative breakdowns
- Theme extraction and representative review surfacing
- Trend charts by week/month/quarter when dates are present
- Question answering with evidence retrieval
- CSV export of cleaned review and sentiment results

## Architecture

- Frontend: Streamlit
- Backend: Python
- Embeddings / retrieval: ChromaDB (fallback keyword embedding when transformers are not installed)
- NLP: NLTK, pandas, scikit-learn
- Charts: Plotly
- Optional LLM: Gemini API

## Installation

1. Create a virtual environment:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Optionally set the Gemini API key for live answer generation:
   ```bash
   set GEMINI_API_KEY=your_key_here
   ```

## Run

```bash
streamlit run app.py
```

Then open the URL shown by Streamlit (usually `http://localhost:8501`).

## Sample Data

The app includes a bundled sample dataset at `data/sample_reviews.csv`.
Use it to verify the dashboard and feature flow before uploading larger datasets.

## Supported CSV Schema

The app expects review data with the following columns:

- `Review` (or a recognized alias like `reviews.text`)
- `Rating` (or `reviews.rating`)
- `Product` (optional)
- `Date` (optional, recommended for trend analysis)

If your file has different column names, the app attempts to auto-map common variants. If mapping fails, use `utils/prepare_kaggle_dataset.py` to inspect and standardize the schema.

## Why the Q&A Answers Were Inaccurate (and the fix)

Two separate bugs combined to make "Ask a Question" answers vague and evidence look irrelevant:

1. **The Q&A step ignored relevance scores entirely.** It always summarized whatever 5 reviews retrieval returned, even ones with a similarity score as low as 0.13 (essentially unrelated). Now it filters to reviews that actually clear a relevance threshold before answering, and the summary references the actual shared theme words from those reviews instead of a generic "positive/negative count" template.
2. **The fallback embedding (used when `sentence-transformers`/torch aren't installed) treated every word as equally important**, so common filler words could outweigh the specific product/complaint words that should have driven the match. It now learns word importance (IDF) from your dataset, so distinctive words like "battery" or "disconnecting" matter more than generic ones.

The **Evidence Explorer** tab now shows exactly the reviews that backed the last answer, not a raw, noisier top-5.

**Note on accuracy ceiling:** without `sentence-transformers`/`torch` installed (or a `GEMINI_API_KEY` set), the app is doing keyword/word-overlap matching, not true semantic understanding ÔÇö it will still occasionally miss paraphrased matches, especially on small datasets (a handful of reviews) where there isn't enough data for word-importance weighting to be reliable. For meaningfully better accuracy: `pip install sentence-transformers torch` for real semantic embeddings, and/or set `GEMINI_API_KEY` so answers are generated by an LLM instead of the deterministic fallback.

## Why Uploading a Raw Kaggle File Crashed ("Review cleaning failed")

Uploading a Kaggle CSV directly (without running `prepare_kaggle_dataset.py` first) used to crash
with a generic `RuntimeError: Review cleaning failed.` This has been fixed at the source:

- **The app now auto-detects column names on upload.** Common variants (Kaggle's `reviews.text`,
  `reviews.rating`, `name`, etc.) are automatically mapped onto `Review`/`Product`/`Rating`/`Date` -
  you can now drag-and-drop a raw Kaggle export directly, no conversion step required. The
  `prepare_kaggle_dataset.py` script still exists for datasets with unusual column names, or if you
  want to pre-sample a huge file yourself.
- **If a file genuinely can't be mapped** (no plausible review-text or rating column), the app now
  shows exactly which columns it found and what it expected, instead of a generic error.
- **Errors no longer crash the whole page.** Any failure during analysis is now caught and shown as
  a message in the app; your previous working dashboard (if any) stays up.
- **Large files are sampled automatically.** A "Max rows to analyze" control in the sidebar
  (default 5,000) keeps huge Kaggle exports (the Datafiniti Amazon dataset is ~95MB/34k rows) from
  making the fallback pipeline hang - raise it if you want more coverage.

## What Was Fixed / Improved

- **Broken retrieval (core bug):** the fallback embedding (used whenever `sentence-transformers` isn't installed) produced a differently-sized vector per review, so cosine similarity always returned 0 and the Q&A / evidence features silently found nothing. Replaced with a fixed-size hashing embedding so retrieval always works, with or without heavy ML dependencies.
- **Re-analysis on every click:** the app previously re-ran the entire pipeline (cleaning ÔåÆ sentiment ÔåÆ embedding ÔåÆ indexing) on *every* interaction, including typing in the question box. It now runs once on load and again only when you click "Analyze Reviews".
- **Vector store crashes on re-run:** indexing used to `add()` the same IDs every analysis, which raises a duplicate-ID error against real ChromaDB. The store is now reset before each indexing pass.
- **Invalid ChromaDB metadata:** a nested dict in the metadata payload is rejected by ChromaDB (metadata values must be primitives); replaced with flat fields.
- **NLTK setup robustness:** lemmatizer and stopword loading no longer wipe each other out if only one resource is missing.
- **Unused/misleading dependencies** (`bertopic`, `beautifulsoup4`) removed from `requirements.txt`; the rest is now split into "core" vs "optional, higher accuracy" so the app's actual behavior without those installs is obvious.
- **Visual refresh:** tabbed layout (Overview / Themes / Trends / Ask a Question / Evidence Explorer), a sentiment donut chart, a per-product stacked sentiment chart, an average-rating KPI, a progress-bar confidence indicator, readable theme/keyword tables, and a CSV download of the cleaned + scored data.
- **Answer accuracy:** Q&A now filters out low-relevance "evidence", weights fallback-embedding words by corpus IDF, and gives question-aware summaries instead of a generic template (see above).
- **Evidence Explorer** now reflects the evidence actually used for your last question instead of always showing a generic preview query.

## Troubleshooting

- If the app shows a session warning, run it with `streamlit run app.py` rather than `python app.py`.
- If your upload fails, ensure the input CSV contains at least `Review` and `Rating` columns.
- Large CSV uploads are sampled to keep analysis responsive; use the sidebar `Max rows to analyze` control.
- For better accuracy, install optional ML dependencies:
  ```bash
  pip install sentence-transformers torch
  ```
